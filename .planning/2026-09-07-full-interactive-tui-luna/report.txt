hya 0.36.13 交互式 TUI 测试报告

结论：不能通过“所有功能均正常”的验收。已按源码盘点 16 个功能族、24 个本地 slash 命令和 27 个 canonical 内置工具，并结合真实 PTY、真实 Luna 请求、现有全部 TUI/workspace/process 测试进行验证。不是所有输入、状态组合与外部集成的穷尽验证。

真实 endpoint：https://api.12th.day/v1
所有 87 次记录到的真实模型请求均为 gpt-5.6-luna。主代理、子代理、Workflow、压缩、goal evaluator 和直接图片对照共用只允许 Luna 的拦截网关；未请求其他真实模型。自动化套件的本地 FakeLlm 不计为真实 endpoint 通过。

明确问题
1. 图片未传到模型：TUI 向后端发送了正确红色 PNG，UI 显示图片附件；后端发到 Responses endpoint 的内容只有 string，input_image 数量为 0。新会话仍答 Blue；直接同 endpoint/同模型/同 PNG 答 Red。
2. Escape 中断无效：观察到流式生成后发送单次、双次 Escape，仍 busy；TUI HTTP 记录没有 /abort。直接 API abort 可停止。仅对本次 Linux/tmux/OpenTUI 环境作此结论，未断言根因。
3. 内置技能目录不一致：/skills 和 GET /skill 展示 agent-bundle-authoring，但 skill 工具按短名和 harness:skill 名称均报 not found；项目自定义 luna-qa 技能能正常加载。
4. Heap snapshot 假成功：执行 Write heap snapshot 显示 Heap snapshot written to undefined；当前入口未提供 onSnapshot 回调。
5. LSP 实际不可用：真实 TypeScript 文件 documentSymbol 也报 No LSP server available for this file type；stock runtime 没有接入 LSP provider。注入式测试成功不代表真实 LSP 可用。

工具覆盖
27 个 canonical 工具全部列入 report.json。24 个有真实成功结果；lsp 只有不可用错误；write/edit 被现代 gpt-* 模型的硬编码过滤排除，Luna 下无法正常暴露。没有换模型或绕过产品过滤。365 项工具层测试包含 write/edit/LSP 注入路径，全部通过，但不冒充真实交互成功。
6 个隐藏别名：shell→bash、patch→apply_patch、fetch→webfetch、search→websearch、todo→todowrite、plan→plan_exit。文档声称 28 个工具并把 shell 当 canonical，与源码不符。
