Give each task a bounded scope, explicit file ownership/non-goals and observable acceptance; copy every hard constraint, edge-case note, and negative requirement verbatim into shared context or the relevant prompt. Avoid overlapping edits; assign one integration owner. Dependent work starts only after its prerequisites are available.

Non-blocking: returns all handles and session IDs after registration, while agents work concurrently subject to runtime limits. Use wait when blocked on reports, then integrate and verify the results. Failed batch entries do not cancel successfully launched siblings; inspect each status and never blindly retry the entire batch.

Choose subagent_type from the available roster (list_agents); omit it for hya-task. Omit effort to use the model#effort suffix or the child's default shown by list_agents. Set it only when the assignment needs a supported override. Omit model/category unless needed; batch overrides belong to each item. The harness names each handle <subagent_type>-<operator>. Send mail to a handle for follow-up, including revival of an archived agent. Shared context is prepended to each prompt; children do not inherit the parent's conversation.

Use tasks with at least one non-empty prompt per item. Do not supply both tasks and its legacy alias members. Legacy single calls use top-level description and prompt, with optional subagent_type and overrides.
