Hya Documentation

Hya 是一个用 Rust 编写的开源编程智能体，为长会话和多智能体协作而生。本页是精简版，完整内容见 文档站。

Overview

Hya 的核心是一份只增不减的事件日志：用户提示、模型输出、工具调用、权限决定、token 用量，每一次变化都记录为事件，再由同一个 reducer 折叠成当前的会话状态。

运行 hya 时，它会找到或启动一个常驻的后台守护进程，并同时打开终端 TUI 和浏览器 WebUI。编辑器（ACP）、无头命令行、SDK 和 gRPC 客户端都连接同一个后台，通过同一份 hya.v1 协议通信。

  • Long-horizon context： 请求超过模型窗口的 80% 时逐级缩减上下文，你的消息逐字保留。
  • Fast and safe： 常驻守护进程、单端口协议；每次工具调用都经过权限检查，远程访问端到端加密。
  • Multiagent： 非阻塞地派出子代理，用 handoff 交接状态、用频道通信，并支持 Workflow DAG。

模型服务商支持 OpenAI（Chat、Responses、Codex 订阅）、Anthropic、Google Gemini、Grok，以及任何 OpenAI 兼容接口。

Installation

Requirements

  • 预编译版本：glibc Linux（x86_64、aarch64）和 Apple silicon macOS。
  • Windows：在 WSL 2 中安装，见 Install on Windows with WSL。
  • 从源码构建：Rust 1.91+、Bun 1.4.2+、Git。

Install

# 安装最新 release 到 ~/.local（含后端、bundle、TUI、WebUI 和 Bun）
curl -fsSL https://hya.ed-aisys.com/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"   # 需要时写进 shell 配置
hya --version

Build from source

git clone https://github.com/chrono-foundry/hya
cd hya
./install.sh --prefix "$HOME/.local"   # --dry-run 只打印计划步骤

Update

hya update                     # 更新到最新稳定版
hya update --version v0.47.0   # 固定到指定版本

安装脚本会校验压缩包的 SHA-256，用重命名整体替换安装目录，失败时自动回滚。更多选项见 Install and Update。

Quick Start

三步跑通第一个任务：

  1. 在项目目录运行 hya：终端打开 TUI，浏览器可以访问 http://127.0.0.1:3250 的 WebUI。
  2. 接入模型：在 TUI 中输入 /key，或运行 hya provider add（见 Configuration）。
  3. 在输入框里描述任务，例如 “summarize this repository's crate boundaries”。
$ cd ~/my-project
$ hya                      # TUI + WebUI（http://127.0.0.1:3250）
$ hya provider add         # 交互式添加服务商：base URL、协议、API key
$ hya exec "summarize this repository's crate boundaries"   # 无头运行一轮

Why Hya?

Hya 的设计围绕一个承诺：会话中的每一次状态变化都写进一份只增不减的事件流，再用同一个 reducer 确定性地折叠。下面这些特性都建立在它之上。

维度Hya 的做法带来什么
上下文管理只有三种显式操作：模型追加、工具追加、Rewrite；超过窗口 80% 时逐级缩减长会话不会悄悄丢掉你的要求，用户消息逐字保留
状态与持久化SQLite 事件日志 + 确定性的 projection断线重连、重启恢复、回放的结果一致
运行方式常驻守护进程；一份 hya.v1 协议，HTTP/SSE/WS 与 gRPC 共用一个端口终端、浏览器、编辑器和 SDK 可以同时操作同一批会话
多智能体分段工作的子代理、handoff 交接、父子频道子代理可以归档后再唤醒，不必重放整段记录
停止判断由引擎和独立的评估者 / 验证者决定任务是否完成干活的代理不能自己宣布“做完了”
安全权限层 + 多根目录边界 + 端到端加密中继默认先问再动手，远程访问不暴露明文

设计细节见 Design Philosophy & Architecture。

Long-Horizon Context

内核只允许上下文通过三种原语变化：

  • 模型追加： 模型输出的文本、推理和工具调用。它只是声明，不是事实。
  • 工具追加： 与调用配对的工具结果，以及你的输入。外部观察只能从这里进来。
  • Rewrite： 移除当前步骤之前的内容，事件日志保持完整。

How it works

  1. 压力： 每轮请求前，内核估算请求的 token 用量。阈值固定为模型窗口的 80%，例如 200k 窗口的阈值是 160,000。
  2. shake： 把保留尾部之外的过时工具输出换成通知，原文移到 artifact://，模型可以用 read 取回。这一步不调用模型。
  3. remote： 仍然超过阈值时，让支持的服务商折叠自己的窗口（OpenAI Responses 的 /responses/compact，用于 openai-response、openai-codex、grok-build 路由）。
  4. Rewrite： 还超过时，内核移除当前步骤之前的内容，留下的标记逐字重复被移除的用户消息和当前 todo 清单。

也可以在 TUI 中用 /summarize 手动缩减。hya exec --bare 不加载 bundle，只有内核自己的 Rewrite。

# ~/.config/hya/config.yaml（默认值）
compaction:
  keep_recent: 6             # shake 保留的最近消息和工具步骤数
  summary_max_tokens: 4096   # 子代理 handoff 的输出上限
  token_accounting: auto     # auto | provider | estimate

Best practices

  • 用 todo 清单记录完成标准，它会随 Rewrite 标记一起保留。
  • 关键约束写进你自己的消息里：Rewrite 会逐字保留用户消息。
  • 让模型把推导出的结论写进可见文本、工作区文件或 todo 清单，而不是只留在私有推理里。
  • 需要旧的工具输出时，用 read 读取通知中的 artifact:// 句柄。

完整说明见 Kernel 和 Compaction。

Fast and Safe

Performance

  • 常驻守护进程： 第一次运行 hya 时启动，之后直接连接；关闭 TUI 不会停掉它。
  • 实时流式： 文本增量以 seq = 0 实时推送、不写磁盘；每个片段结束时用一次 SQLite 事务提交。
  • 热加载： 安装或更新 bundle、修改项目插件、重连 MCP 都不用重启后台；进行中的轮次继续使用原来的配置。
  • 升级恢复： 升级二进制时先排空进行中的轮次、记下被中断的会话，新进程启动后提示模型接着做。

在源码仓库里可以用 cargo run -p xtask -- startup-bench 测量启动耗时。

Safety

每次工具调用都经过权限层。permission.model 决定默认行为：

ModelBehavior
allow匹配到 deny 就拒绝，否则放行，不会询问
default最后一条匹配的规则生效；没有匹配时，本地只读工具和 task 放行，其他工具、MCP 和命令先询问
strict匹配到 deny 就拒绝，否则都询问（之前选过“始终允许”的同一对象除外）
danger全部放行，连显式 deny 规则也跳过（等同 --yolo）
  • 会话权限模式： 在 TUI 中按 Shift+Tab 在 manual、yolo 和 bundle 定义的模式之间切换，对整棵会话树生效。
  • 目录边界： 文件工具只能访问会话所属 Project 的根目录（解析符号链接后再判断），越界需要批准。
  • 无头模式： exec、-p、loop 中没人回答询问，所有询问一律拒绝。
  • 远程访问： hya proxy 只转发密文，后端和客户端之间是 Noise_NKpsk0 端到端加密隧道。

Note： --yolo 会自动批准所有工具操作。在 hya serve 上使用时，任何能驱动工具的客户端都能执行命令，请只在受信任的环境中使用。hya:// 中继链接也要像私钥一样保管。

Multiagent

主代理用 task 工具派出一个或多个子代理。调用不会阻塞：每个成员立刻返回句柄和会话，结果之后以邮件形式送回。

Episode lifecycle

  1. 派发： task 在一个事务里登记一批成员，每个成员有自己的会话，以及和父代理之间的 #DM 频道。
  2. 工作： 子代理在 working 和 idle 之间切换，收到 DM 邮件就会被唤醒。
  3. 报告： 子代理调用 report（要求收件箱已读完、直接子代理都已归档）。Hya 生成状态交接（handoff），归档它，并把结果邮件送回父代理。
  4. 唤醒： 父代理给已归档的子代理发 DM，它会带着上一次的 handoff 开始新一段工作。

Channels & budgets

  • #DM-… 是父代理与直接子代理之间的私聊；#announce-… 由组长广播，兄弟之间互相看不到。
  • 嵌套深度固定为两层子代理。
  • subagents.max_concurrency（默认 100）限制同时运行的成员数；per_team_turn_budget 和 per_team_message_budget（默认各 1024）超出时终止整个团队，防止失控的循环。

Workflows, Goal & Loop

hya workflow list                      # 项目、用户和 bundle 中的 Workflow
hya workflow info plan-impl-review
hya -p "make all unit tests in hya-proto pass" --max-iterations 6
hya loop --target "formatting and hya-tool tests pass" \
  --until "cargo fmt --all --check && cargo test -p hya-tool" --budget 8

Workflow 是一份 Markdown 文档（*.hya.md），把多个 Agent 编排成有向无环图，放在 .hya/workflows/ 或 ~/.config/hya/workflows/。hya -p（Goal 模式）和 hya loop 由独立的评估者或 shell 条件决定何时停止。见 Workflows 和 Subagent Orchestration。

Configuration

配置文件位于 ~/.config/hya/config.yaml（或 $XDG_CONFIG_HOME/hya/config.yaml），所有顶层字段都是可选的。

KeyDefaultDescription
default_model—默认的 provider/model，可以带 #effort 后缀
default_agenthya-main根会话默认使用的 Agent
reasoning—全局默认推理强度：none、minimal、low、medium、high、xhigh、max
providers.<id>—模型路由：kind、base_url、api_key、models
permission.modeldefaultallow / default / strict / danger
subagents.max_concurrency100同时运行的子代理成员上限
compaction.keep_recent6shake 保留的最近消息和工具步骤数

# 最小可用配置
default_model: anthropic/claude-sonnet-4-6

providers:
  anthropic:
    kind: anthropic
    base_url: https://api.anthropic.com/v1
    api_key: "{env:ANTHROPIC_API_KEY}"
    models: [claude-sonnet-4-6]

凭据也可以用 hya login anthropic "$ANTHROPIC_API_KEY" 单独保存，它优先于配置里的 api_key。ChatGPT Codex 和 Grok 订阅用 hya oauth login。守护进程运行时手动改了 providers，运行 hya serve restart 或在 /key 中刷新。完整字段见 Configuration Guide。

FAQ

没有 API Key 能用吗？

可以。没有可用的服务商时，Hya 使用内置的离线回显模型 hya/offline，所有界面都能打开。准备好之后用 /key 或 hya provider add 接入真实模型。

关掉 TUI 之后，后台还在运行吗？

在。按两次 Ctrl+C 或输入 /exit 只关闭 TUI 和 WebUI，守护进程继续运行，下次启动直接连接。用 hya serve status 查看，hya serve stop 停止。

提示 WebUI 端口 3250 被占用？

通常是另一个 hya 正在用这个端口，TUI 本身照常工作。用 hya --port 3251 换一个端口，或 hya --port 0 让系统自动选择。

能在 Windows 上用吗？

请在 WSL 2 中安装，Windows 上的浏览器可以访问 WebUI。见 Install on Windows with WSL。

无头模式下写文件或执行命令失败？

hya exec、-p 和 loop 中没人回答权限询问，所以询问一律拒绝。可以在 permission.rules 里显式允许需要的命令，或在受信任的环境中使用 --yolo。

怎么从另一台电脑访问服务器上的 Hya？

使用加密中继：在任意可达的机器上运行 hya proxy，在后端运行 hya serve start --relay <url> 得到 hya:// 链接，再在本地用 hya --connect - 粘贴链接连接。见 Secure Relay。

其他问题见 Troubleshooting。
