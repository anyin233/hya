Quick Start

一条命令安装预编译版本，后端、首方 bundle、TUI、WebUI 和自带的 Bun 运行时都装进 ~/.local。在项目目录运行 hya，终端里打开 TUI，浏览器里打开 http://127.0.0.1:3250 的 WebUI，两边连接同一个后台、共享同一批会话。

用 hya provider add 或在 TUI 中输入 /key，接入 OpenAI、Anthropic、Google Gemini、Grok 或任何 OpenAI 兼容接口。Windows 用户请在 WSL 2 中安装。

完整步骤见 使用文档。

Why Hya?

编程智能体的会话越拉越长：上下文被塞满，早先的要求被悄悄丢掉，多个代理并行时状态也容易乱。Hya 从底层就为这些情况设计。

一切都是事件。 用户提示、模型输出、工具调用、权限决定、token 用量，都追加到 SQLite 事件日志里，再由同一个 reducer 折叠成会话状态。断线重连、重启恢复、命令行回放看到的是同一份历史。

一个后台，多个入口。 后台守护进程常驻运行。终端 TUI、浏览器 WebUI、编辑器（ACP）、SDK 和 gRPC 客户端都通过同一份 hya.v1 协议连接同一个端口。

Architecture

Long-Horizon Context

Hya 的上下文只通过三种显式操作变化：模型追加（模型说的话）、工具追加（工具观察到的结果和你的输入）、Rewrite（腾出空间）。模型说的话只算声明，外部事实只能通过工具追加进来。

逐级缩减： 每轮请求前，内核检查请求是否超过模型窗口的 80%。超过时先 shake，把过时的工具输出换成通知；还超就让支持的服务商原生压缩；最后才由内核 Rewrite。

你的话不丢： Rewrite 留下的标记会逐字重复被移除的用户消息，并带上当前的 todo 清单。被移出的内容仍留在日志里，客户端始终能看到完整输出。

How It Works

Fast and Safe

Hya 用 Rust 编写。后台守护进程在 TUI 关闭后继续运行，再次运行 hya 时直接连上。模型输出的文本增量实时推送、不写磁盘，每个片段结束时用一次事务提交。

Fast： 一个守护进程、一个端口、一份协议。bundle、插件和 MCP 可以热加载，不必重启后台；升级二进制时会记下被中断的会话，重启后提示模型接着做。

Safe： 每次工具调用都要经过权限层，按 allow / ask / deny 规则判断。文件工具只能访问会话所属 Project 的根目录，越界要你批准。远程访问走端到端加密的中继，中继只看得到密文。

Permissions

Multiagent Supported

主代理用 task 派出子代理，调用立刻返回，子代理在各自的会话里并行工作。子代理完成后调用 report：Hya 生成一份状态交接（handoff），归档这个子代理，并把结果作为邮件送回父代理。

父子之间通过频道通信：#DM 是父子私聊，#announce 由组长广播。给已归档的子代理发 DM，它会带着上一次的 handoff 继续工作。嵌套固定为两层，并发数和消息量都有预算上限，防止失控。

需要固定流程时，用 Markdown 写一份 Workflow（*.hya.md），把多个 Agent 编排成 DAG。

设计一览

Hya 把会话当成一份只增不减的事件日志，在它之上搭起内核、协议、前端和扩展。下面是几个关键设计。

阅读架构文档

  • 事件溯源

    会话的每一次变化都追加到 SQLite 事件日志，由同一个 reducer 折叠。回放、重连和恢复的结果一致。

  • 一份协议

    hya.v1 有 18 个服务、109 个 RPC。HTTP/JSON、SSE、WebSocket 和 gRPC 共用一个端口。

  • 加密远程访问

    hya proxy 只转发密文。后端和你的电脑之间是端到端的 Noise 加密隧道。

  • Bundle 扩展

    用 .hyabundle 打包 Agent、Workflow、技能、MCP 和侧车进程，也能导入 Claude Code 插件。

  • 终端与浏览器

    同一个 OpenTUI 界面跑在终端里，也通过真实 PTY 和 xterm.js 显示在浏览器中。

  • 三原语内核

    模型追加、工具追加、Rewrite。hya exec --bare 只运行内核和 6 个内置工具。
