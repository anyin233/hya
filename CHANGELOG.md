# 0.48.0-dev.29

- **Bare mode: a round whose stream breaks after it produced output is retried.** When the model stream stalls or breaks, or a transient error arrives, after the round has already produced reasoning, text or a tool call, the round is now retried under the same rule as before (up to eight retries after 5, 10, 20, 40, 60, 60, 60 and 60 seconds). The failed attempt's parts are removed from the conversation with `part_deleted` events before the wait; they stay in the event log. Nothing of a failed attempt was ever executed. Before, any output in the attempt ruled the retry out, so with reasoning enabled an interrupted stream ended the run.
- **A round whose stream breaks after its final frame counts as complete.** In both modes, a body error that arrives after the response's final frame no longer fails the round: the answer, tool calls and usage it carried are kept.
- **Bare mode: a turn without an answer and without a tool call no longer ends the run.** Such a turn (for example reasoning cut off at a service's output limit) gets one logged notice and another round, at most twice in a row, and does not use up the completion check.
- **The note on an earlier tool-result image no longer reads like a failure.** A tool-result image is sent once, in the request after the call; later requests carry a note instead. The note now says that this is the normal course and how to see the image again. Models had read the old wording ("is not attached to this request") as a failed attachment and stopped using images.
- **v1 event stream: `partDeleted`.** `StreamEvent` has a new payload that tells a client to drop a part by id (an explicit part deletion, or a retried bare attempt). Additive: older clients ignore it. The SDK's session mirror applies it.
