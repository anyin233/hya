# 0.48.0-dev.36

- **TUI structure presets, skills and user commands.** `tui.toml` structure presets (with a status line by default, plus a dock preset with a band input and todo and subagent rows), an auto theme that follows the terminal background, paste chips and image paste from the system clipboard, a startup list of loaded resources, and `/reload` and `/reload-<target>`. Skills run as `/skill:<name>` and are listed in a `/skills` view; a session agent's bundle and plugin skills are included, skipped skill files are reported, and `disable-model-invocation` is honoured. User commands gain argument hints, scopes and pi template syntax. `RefreshSessionContext` re-records a session's initial context, and bootstrap lists the loaded context files. The WebUI uploads pasted and dropped files.
- **Claude adapter in releases.** The release archive, the source installer and `hya update` now ship `lib/hya/claude-adapter`, so `hya bundle install --claude` and `kind: claude` plugins work from an installed prefix without `HYA_CLAUDE_ADAPTER_DIR`. CI, the release rehearsal and the source installer stage the archive through one xtask staging step.
- **Fixes.** Full-mode startup reports a native rewriter that fails to load (with the bundle ID and loader error) instead of panicking. Each model round, handoff and catalog read uses one provider snapshot, so a provider refresh cannot switch routes mid-operation. Native Responses compaction honours the route's response-header deadline and returns typed HTTP errors capped at 500 characters. `webfetch` stops reading a response as soon as it exceeds the size cap and reuses one HTTP client. Bare and full-mode `read` share image decode validation and the attachment size limit, so a truncated image is reported instead of attached. A `.` path joined to a `.` workdir stays `.` in the LSP tools. The extended-tools bundle lists all of its native sources. The TUI's packaged protobuf files are generated by `gen-api`, and CI checks every generated API output for drift.
- **Provider internals.** Auth headers are built in one place with secret strings; protocol quirks live on `Protocol`; Gemini inline media is validated without decoding a full copy; provider IDs are validated by one function shared by the app, HTTP API and CLI. The scripted `FakeProvider` moves behind the `hya-provider` `test-support` feature, and a standalone backend build no longer contains it.
- **Rust API changes for embedders.** Crate boundaries were redrawn, and paths whose deprecated re-export would need a dependency cycle (or keep the dependency being removed) moved without one:
  - `hya_store::BundleRegistry` and its errors → `hya_app::bundle_registry` (the on-disk `registry.db` is unchanged);
  - `hya_tool::{ToolRegistry::builtins, ToolRegistry::from_tool_families, native_bundle::load, native_bundle::loaded_library_sources}` and the base-tools preset items → the new `hya-tool-loader` crate; `hya-tool` and the native tool libraries no longer depend on `hya-bundle`, `sevenz-rust2` or `serde_norway`;
  - skill catalog discovery and `BuiltinFormatterProvider` → `hya-app`;
  - `hya_plugin::activation` → `hya_app::runtime::sidecar`, and the engine hook implementations for plugin hosts → `hya_app::plugin_adapter::PluginHostAdapter` (`hya-plugin` no longer depends on `hya-engine`);
  - token accounting and the rewrite contract → the new `hya-context` crate (deprecated re-exports remain in `hya-tool`); `hya_mcp::{codec, io_tasks}` → the new `hya-child-io` crate (deprecated re-exports remain);
  - `hya serve` and `HyaRuntime` share one startup and one shutdown sequence in `hya-app`, which also owns headless goal/loop setup, the bare runner and read-only Workflow inspection; runtime-owner contention is a typed `hya-app` error;
  - deprecated: `BUN_ADAPTER_VERSION`, `CLAUDE_ADAPTER_VERSION`, `CLAUDE_PLUGIN_KIND`, `PLUGIN_MANIFEST_FILE`, and `hya_server::valid_provider_id`.
- **Internal restructuring.** Module splits without behaviour change in the engine (façade, runtime registry, hooks, mailbox, resident actors, Workflow runs), the app config, the store, `output_cap`, and the TUI controller and slash commands; one inbox reader over the projection for wake and catch-up; bound resources selected once per binding; one install-planning function for user and Project bundles; shared preference validation; shared CLI and server provider upserts.
