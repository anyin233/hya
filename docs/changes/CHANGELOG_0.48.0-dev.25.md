# 0.48.0-dev.25

- **A run no longer ends because its session database stalls or fails.** Every append goes through one writer task in order. When a write takes longer than 2 seconds or the storage fails (locked by another process, disk full, I/O error), the run goes on from memory, the queued events are written when the storage answers again, and at exit hya waits up to 30 seconds and prints one line on stderr: recovered, or how many events and bytes are not on disk and why. A process killed in that state loses the queued events. Design and limits: ADR-0036.
- **One-shot headless runs start without a usable database.** `exec`, `exec --bare`, `-p` and a directly run workflow fall back to an in-memory store when the database cannot be opened within 5 seconds or the open fails with a storage error; hya says so once at start and at exit ("nothing was persisted"). `serve`, the daemon and the commands that act on stored sessions still fail with the reason; a database owned by another runtime still exits 75.
- **A database file that is deleted or replaced under a run is left alone.** hya stops writing to the path, never writes into the replacement, finishes the run from memory and reports what was not persisted.
- **Reads fall back only where a run needs them.** When the store cannot be read within 5 seconds: a file edit is recorded without its before-state (it cannot be reverted from the log), a running turn keeps the effort preference it read last, and a full-mode `exec --json` stream may be incomplete and says so once on stderr.
- **Stop signals reach the store.** On SIGINT or SIGTERM the headless commands drain the store and print the durability line before exiting 130 or 143; a signal during that drain prints the current state and exits at once. `serve stop` and `restart` wait 45 seconds by default.
- **Store internals.** One pinned writer connection plus a read-only pool; sequence numbers are assigned in process; a raw transaction's commit is resolved by a task that owns it.
